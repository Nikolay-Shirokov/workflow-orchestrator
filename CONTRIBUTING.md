# Руководство по внесению вклада в Workflow Orchestrator

Спасибо за интерес к проекту! Мы рады любому вкладу - от сообщений об ошибках до новых функций.

## Как внести вклад

### Сообщения об ошибках

Если вы нашли ошибку:

1. Проверьте, нет ли уже [похожего issue](https://github.com/Nikolay-Shirokov/workflow-orchestrator/issues)
2. Создайте [новый issue](https://github.com/Nikolay-Shirokov/workflow-orchestrator/issues/new) с описанием:
   - Шаги для воспроизведения
   - Ожидаемое поведение
   - Фактическое поведение
   - Версия Node.js и ОС
   - Версия workflow-orchestrator

### Предложения новых функций

Если у вас есть идея:

1. Проверьте [существующие issues](https://github.com/Nikolay-Shirokov/workflow-orchestrator/issues)
2. Создайте issue с тегом "enhancement"
3. Опишите:
   - Проблему, которую решает функция
   - Предлагаемое решение
   - Альтернативные варианты

### Pull Requests

#### Подготовка

1. Форкните репозиторий
2. Клонируйте свой форк:
   ```bash
   git clone https://github.com/ваш-username/workflow-orchestrator.git
   cd workflow-orchestrator
   ```

3. Установите зависимости:
   ```bash
   npm install
   ```

4. Создайте ветку для вашей функции:
   ```bash
   git checkout -b feature/amazing-feature
   ```

#### Разработка

1. Внесите изменения в код
2. Добавьте тесты для новой функциональности
3. Убедитесь, что все тесты проходят:
   ```bash
   npm test
   ```

4. Проверьте покрытие тестами:
   ```bash
   npm run test:coverage
   ```

5. Проверьте код линтером:
   ```bash
   npm run lint
   ```

6. Соберите проект:
   ```bash
   npm run build
   ```

#### Стиль кода

- Используйте TypeScript
- Следуйте существующему стилю кода
- Добавляйте комментарии на русском языке для сложной логики
- Используйте осмысленные имена переменных и функций

#### Тестирование

- Добавляйте unit тесты для новых функций
- Добавляйте интеграционные тесты для сложных сценариев
- Стремитесь к покрытию не менее 90%
- Тесты должны быть понятными и поддерживаемыми

#### Документация

- Обновите README.md при необходимости
- Добавьте примеры использования новой функции
- Обновите соответствующие файлы в docs/
- Добавьте комментарии JSDoc для публичных API

#### Коммиты

Используйте понятные сообщения коммитов:

```
feat: добавлена поддержка параллельного выполнения
fix: исправлена ошибка в парсере DSL
docs: обновлена документация по установке
test: добавлены тесты для state-manager
refactor: улучшена структура адаптеров
```

Префиксы:
- `feat`: новая функция
- `fix`: исправление ошибки
- `docs`: изменения в документации
- `test`: добавление или изменение тестов
- `refactor`: рефакторинг кода
- `perf`: улучшение производительности
- `chore`: обновление зависимостей, конфигурации и т.д.

#### Отправка PR

1. Зафиксируйте изменения:
   ```bash
   git add .
   git commit -m "feat: описание изменений"
   ```

2. Отправьте в свой форк:
   ```bash
   git push origin feature/amazing-feature
   ```

3. Откройте Pull Request на GitHub

4. В описании PR укажите:
   - Что изменено и почему
   - Ссылку на связанный issue (если есть)
   - Скриншоты (если применимо)
   - Результаты тестирования

#### Ревью

- Будьте готовы к обсуждению и изменениям
- Отвечайте на комментарии ревьюеров
- Вносите запрошенные изменения
- После одобрения PR будет смержен
