# Примеры использования тегов для обрамления контекста

## Обзор

Этот документ содержит примеры использования тегов для обрамления вложенного контекста в промптах.
Теги помогают AI-моделям четко различать границы разных частей данных.

## Пример 1: Простое обрамление одного артефакта

### Промпт без тегов

```
Проанализируйте следующие вопросы:

${copilot_questions}

Предоставьте детальный анализ.
```

### Промпт с тегами

```
Проанализируйте следующие вопросы:

${artifact:${copilot_questions_file}:questions}

Предоставьте детальный анализ.
```

### Результат с тегами

```
Проанализируйте следующие вопросы:

<questions>
# Вопросы второго пилота

1. Какова основная бизнес-цель проекта?
2. Кто является целевой аудиторией?
3. Какие ключевые метрики успеха?
</questions>

Предоставьте детальный анализ.
```

## Пример 2: Множественные артефакты с разными тегами

### Промпт

```
Объедините информацию из следующих источников:

## Технический анализ
${artifact:${architect_analysis_file}:technical}

## Бизнес-анализ
${artifact:${copilot_analysis_file}:business}

## Результаты исследования
${artifact:${research_file}:research}

Создайте единый документ требований, учитывая все аспекты.
```

### Результат

```
Объедините информацию из следующих источников:

## Технический анализ
<technical>
# Технический анализ

## Архитектурные решения
- Микросервисная архитектура
- REST API
- PostgreSQL база данных
</technical>

## Бизнес-анализ
<business>
# Бизнес-анализ

## Бизнес-цели
- Увеличение конверсии на 20%
- Снижение времени обработки заказов
</business>

## Результаты исследования
<research>
# Результаты исследования

## Конкурентный анализ
- Конкурент A: использует технологию X
- Конкурент B: фокусируется на Y
</research>

Создайте единый документ требований, учитывая все аспекты.
```

## Пример 3: Вложенные данные с кодом

### Промпт

```
Проверьте следующий код на соответствие требованиям:

## Требования
${requirements}

## Код для проверки
${artifact:${code_file}:code}

Укажите все несоответствия и предложите исправления.
```

### Результат

```
Проверьте следующий код на соответствие требованиям:

## Требования
- Функция должна обрабатывать ошибки
- Код должен быть типизирован
- Необходимо логирование

## Код для проверки
<code>
function processData(data) {
  return data.map(item => item.value);
}
</code>

Укажите все несоответствия и предложите исправления.
```

## Пример 4: Комбинирование прямого содержимого и тегов

### Промпт

```
Создайте финальный документ на основе следующей информации:

## Исходный запрос (прямое содержимое)
${user_request}

## Детальные вопросы (с тегами для структуры)
${artifact:${final_questions_file}:questions}

## Ответы пользователя (прямое содержимое)
${user_answers}

## Результаты исследования (с тегами для больших данных)
${artifact:${research_file}:research}

Структурируйте всю информацию в единый документ требований.
```

### Когда использовать каждый подход

**Прямое содержимое (`${variable}`):**
- Короткие данные (< 1000 символов)
- Простые текстовые блоки
- Когда не нужно явное разграничение

**Теги (`${artifact:${variable_file}:tag}`):**
- Большие объемы данных (> 1000 символов)
- Структурированные данные (JSON, YAML, код)
- Множественные артефакты в одном промпте
- Когда нужны четкие границы для AI-модели

## Пример 5: Реальный промпт из dual-design workflow

### Старый вариант (без оптимизации)

```
# Шаблон промпта: Анализ вопросов архитектором

Вы - АРХИТЕКТОР, анализирующий вопросы второго пилота.

## Вопросы второго пилота

${artifact:${copilot_questions_file}}

## Задача

Проанализируйте вопросы второго пилота с технической точки зрения.
```

### Новый вариант (оптимизированный)

```
# Шаблон промпта: Анализ вопросов архитектором

Вы - АРХИТЕКТОР, анализирующий вопросы второго пилота.

## Вопросы второго пилота

${copilot_questions}

## Задача

Проанализируйте вопросы второго пилота с технической точки зрения.
```

### Вариант с тегами (для больших данных)

```
# Шаблон промпта: Анализ вопросов архитектором

Вы - АРХИТЕКТОР, анализирующий вопросы второго пилота.

## Вопросы второго пилота

${artifact:${copilot_questions_file}:copilot_questions}

## Задача

Проанализируйте вопросы второго пилота с технической точки зрения.
```

## Рекомендации по выбору подхода

### Используйте прямое содержимое когда:
- ✅ Данные уже в памяти (outputs предыдущих шагов)
- ✅ Размер данных < 100KB
- ✅ Не нужно явное разграничение
- ✅ Простой текст без сложной структуры

### Используйте теги когда:
- ✅ Большие объемы данных (> 1000 символов)
- ✅ Несколько артефактов в одном промпте
- ✅ Структурированные данные (JSON, YAML, XML, код)
- ✅ Нужны четкие границы для AI-модели
- ✅ Вложенные уровни данных

### Используйте загрузку из файла когда:
- ✅ Файл может быть изменен внешним процессом
- ✅ Нужна гарантия актуальности данных
- ✅ Данные слишком большие для хранения в памяти

## Производительность

### Сравнение подходов

| Подход | Скорость | Память | Актуальность | Читаемость |
|--------|----------|--------|--------------|------------|
| Прямое содержимое | ⚡⚡⚡ Быстро | 📊 Средне | ✅ Гарантирована | ⭐⭐⭐ Отлично |
| Загрузка из файла | ⚡⚡ Средне | 📊 Низко | ✅ Гарантирована | ⭐⭐ Хорошо |
| С тегами | ⚡⚡ Средне | 📊 Низко | ✅ Гарантирована | ⭐⭐⭐ Отлично |

### Кэширование

Система автоматически кэширует загруженные артефакты на 5 минут:
- Первая загрузка: ~50мс (чтение файла)
- Повторная загрузка: ~10мс (из кэша)
- Прямое содержимое: ~1мс (уже в памяти)

## Заключение

Выбор подхода зависит от конкретной ситуации:

1. **По умолчанию**: Используйте прямое содержимое (`${variable}`)
2. **Для больших данных**: Добавьте теги (`${artifact:${variable_file}:tag}`)
3. **Для актуальности**: Загружайте из файла (`${artifact:${variable_file}}`)

Все три подхода совместимы и могут использоваться в одном промпте.
