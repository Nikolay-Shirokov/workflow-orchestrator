# Быстрый старт: Создание бизнес-требований

Это краткое руководство поможет вам за 5 минут начать создавать бизнес-требования.

## Шаг 1: Установка (если еще не установлено)

> **Примечание:** Пакет пока не опубликован на npm. Используйте установку из исходников.

```bash
git clone https://github.com/anthropics/workflow-orchestrator.git
cd workflow-orchestrator
npm install
npm run build
npm link  # Опционально: для глобальной команды workflow-orchestrator
```

Без `npm link` можно запускать напрямую:
```bash
node dist/cli/cli.js run examples/business-requirements-simple.yaml
```

## Шаг 2: Настройка API ключа

```bash
# Для Claude (рекомендуется)
export ANTHROPIC_API_KEY="your-api-key"

# Или для OpenAI
export OPENAI_API_KEY="your-api-key"
```

## Шаг 3: Запуск

### Вариант A: Упрощенная версия (быстро)

```bash
workflow-orchestrator run examples/business-requirements-simple.yaml
```

**Что произойдет:**
1. Откроется файл для описания вашей идеи
2. AI сформирует вопросы
3. Вы ответите на вопросы в файле
4. Получите готовый документ требований

**Время:** ~10-15 минут

### Вариант B: Полная версия (детально)

```bash
workflow-orchestrator run examples/business-requirements-workflow.yaml
```

**Что произойдет:**
1. Откроется файл для описания вашей идеи
2. Две AI-модели сформируют и проанализируют вопросы
3. Вы получите оптимизированный список вопросов
4. Ответите на вопросы в файле
5. Получите детальный документ с ревью

**Время:** ~20-30 минут

## Шаг 4: Работа с файлами

### Когда откроется редактор:

1. **Заполните информацию**
   - Будьте конкретны
   - Приводите примеры
   - Не бойтесь добавлять детали

2. **Сохраните файл**
   - Ctrl+S (Windows/Linux)
   - Cmd+S (Mac)

3. **Выберите действие**
   - Используйте стрелочки ↑↓
   - **Продолжить** (по умолчанию) - продолжить процесс
   - **Отложить** - сохранить и выйти

4. **Нажмите Enter**

### Если нужно вернуться позже:

```bash
# Найдите ID сессии
ls artifacts/

# Возобновите
workflow-orchestrator resume session_20260113_120000 \
  examples/business-requirements-workflow.yaml
```

## Шаг 5: Получение результата

Результаты сохраняются в `artifacts/requirements-[timestamp]/`:

- `step1_user_need.md` - ваше описание
- `step8_final_questions.md` - финальные вопросы
- `step9_user_answers.md` - ваши ответы
- `step12_final_requirements_v2.md` - **ГОТОВЫЙ ДОКУМЕНТ** ⭐

## Пример заполнения

### Описание потребности (Шаг 1)

```markdown
## Что вы хотите создать/решить?

Я хочу создать веб-приложение для управления задачами команды.
Основная проблема - текущие инструменты слишком сложные для малых команд.

## Для кого это предназначено?

Малые команды разработчиков (5-15 человек), работающие удаленно.

## Какие у вас есть ограничения или предпочтения?

- Бюджет: до $5000
- Срок: 3 месяца
- Технологии: предпочтительно веб-технологии
- Должно работать на мобильных устройствах

## Дополнительная информация

Команда использует Slack для коммуникации, было бы здорово интегрироваться.
```

### Ответы на вопросы (Шаг 9)

```markdown
### Вопрос 1: Какие основные функции должны быть в MVP?

1. Создание и редактирование задач
2. Назначение задач членам команды
3. Отслеживание статуса (todo, in progress, done)
4. Простой канбан-борд
5. Базовые уведомления

### Вопрос 2: Какие роли пользователей нужны?

- Администратор (полный доступ)
- Участник команды (создание и редактирование своих задач)
- Наблюдатель (только просмотр)

[и так далее...]
```

## Что вы получите

Финальный документ будет включать:

✅ **Краткое описание проекта**
- Цель, аудитория, ценность

✅ **Функциональные требования**
- Must-have и nice-to-have функции
- Детальное описание каждой

✅ **Нефункциональные требования**
- Производительность, безопасность, масштабируемость

✅ **Сценарии использования**
- User stories
- Пошаговые сценарии

✅ **Сценарии тестирования**
- Критерии приемки
- Тестовые случаи

✅ **Диаграммы (Mermaid)**
- Диаграммы последовательности
- Диаграммы компонентов

✅ **Ограничения и зависимости**

✅ **Критерии успеха и метрики**

## Советы для лучшего результата

### ✅ Делайте

- Будьте конкретны в описаниях
- Приводите примеры
- Указывайте цифры (пользователи, объемы данных)
- Описывайте контекст использования
- Добавляйте дополнительную информацию

### ❌ Избегайте

- Общих фраз ("должно быть удобно")
- Технических деталей реализации (это для дизайна)
- Противоречивых требований
- Слишком амбициозных целей для MVP

## Troubleshooting

### Редактор не открывается

```bash
# Укажите редактор явно
export EDITOR="vim"
# или
export EDITOR="nano"
```

### Процесс завис

```bash
# Ctrl+C для остановки
# Затем возобновите
workflow-orchestrator resume <session-id> examples/business-requirements-workflow.yaml
```

### Нужно изменить ответы

1. Найдите файл в `artifacts/`
2. Отредактируйте его
3. Возобновите процесс

## Следующие шаги

После получения требований:

1. **Поделитесь с командой**
   - Обсудите требования
   - Соберите обратную связь

2. **Используйте для планирования**
   - Оценка сроков
   - Распределение задач
   - Определение приоритетов

3. **Создайте дизайн**
   - Архитектура системы
   - Технические решения
   - Прототипы

4. **Начните разработку**
   - Используйте требования как референс
   - Отмечайте выполненные пункты
   - Обновляйте при необходимости
