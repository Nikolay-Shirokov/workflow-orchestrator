# Задача 13: Включение вопросов в файл ответов пользователя

## Проблема 1: Вопросы не включались в файл ответов

При выполнении workflow файл `answers_input.md` не содержал вопросы из `questions.md`. Пользователь видел только пустой шаблон без контекста, что затрудняло заполнение ответов.

### Пример проблемы

**Ожидалось:**
```markdown
# Ответы на вопросы

- Для какой основной задачи пользователи будут использовать распознанный текст?
- Что должно происходить с текстом после распознавания?
- На каких операционных системах должно работать решение?

---

**Напишите ваши ответы ниже:**

[Ваши ответы]
```

**Получалось:**
```markdown
# Ответы на вопросы

## Ваш ответ

<!-- Напишите ваш ответ здесь -->
```

### Причины

1. **Неправильное использование полей конфигурации**: использовалось `prompt_template` вместо `prompt_message`
2. **Отсутствие рендеринга переменных**: `TemplateGenerator` не рендерил переменные в `prompt_message`

### Решение

1. Добавлен рендеринг переменных в `TemplateGenerator.generate()`
2. Исправлена конфигурация: `prompt_template` → `prompt_message` для шага `answers`

**Результат**: Файл `answers_input.md` теперь содержит вопросы ✅

## Проблема 2: Вопросы и инструкции сохранялись в финальных ответах

После заполнения файл `answers.md` содержал не только ответы, но и вопросы с инструкциями. Это загромождало контекст для следующих шагов workflow.

### Пример проблемы

**Файл answers.md содержал:**
```markdown
- Каково основное предназначение распознанного текста?
- Для какой операционной системы создается решение?
- Как пользователь будет запускать процесс распознавания?
- Требуется ли работа без подключения к интернету?
- Можете описать наиболее частый сценарий использования?

---

**Напишите ваши ответы ниже (по одному ответу на строку):**

1. Скопировать в буфер обмена
2. В первую очередь для Windows
3. Давай предусмотрим оба варианта
4. Из удаленного рабочего стола
```

**Ожидалось (только ответы):**
```markdown
1. Скопировать в буфер обмена
2. В первую очередь для Windows
3. Давай предусмотрим оба варианта
4. Из удаленного рабочего стола
```

### Решение

#### 1. Инструкции оформлены как HTML-комментарии

```yaml
# examples/business-requirements-simple.yaml
prompt_message: |
  # Ответы на вопросы
  
  ${questions}
  
  ---
  
  <!-- Напишите ваши ответы ниже (по одному ответу на строку) -->
  
  [Ваши ответы]
```

HTML-комментарии автоматически удаляются методом `removeHtmlComments()`.

#### 2. Улучшен метод `parseMarkdown()` в `UserInputHandler`

```typescript
// src/core/user-input-handler.ts
private parseMarkdown(input: string): Record<string, string> | string {
  // Удаляем HTML-комментарии
  let cleanedInput = this.removeHtmlComments(input);
  
  // Удаляем заголовки первого уровня
  cleanedInput = this.removeTopLevelHeaders(cleanedInput);
  
  // Проверяем наличие разделителя ---
  // Если есть, извлекаем только текст после него (это ответы пользователя)
  if (cleanedInput.includes('---')) {
    const parts = cleanedInput.split('---');
    if (parts.length >= 2) {
      // Берем все после последнего разделителя
      const afterSeparator = parts[parts.length - 1].trim();
      
      // Удаляем служебные подсказки в [квадратных скобках]
      const cleanedAnswers = afterSeparator
        .replace(/\[[^\]]+\]/g, '')    // Удаляем текст в [скобках]
        .trim();
      
      if (cleanedAnswers) {
        cleanedInput = cleanedAnswers;
      }
    }
  }
  
  // ... остальная логика парсинга
}
```

**Логика обработки:**
1. Удаляются HTML-комментарии (`<!-- ... -->`)
2. Удаляются заголовки первого уровня (`# Заголовок`)
3. Текст разделяется по `---`
4. Берется только часть после разделителя (ответы)
5. Удаляются служебные подсказки в `[квадратных скобках]`

## Важные замечания

### Разница между `prompt_template` и `prompt_message`

| Поле | Тип шага | Назначение | Рендеринг |
|------|----------|------------|-----------|
| `prompt_template` | `model` | Генерация промпта для AI-модели | Да, в StepExecutor |
| `prompt_message` | `user_input` | Генерация шаблона файла для пользователя | Да, в TemplateGenerator |

### Использование разделителя `---`

Разделитель `---` используется для отделения контекста (вопросов) от области ввода (ответов):
- **До разделителя**: вопросы, инструкции (отбрасываются при парсинге)
- **После разделителя**: ответы пользователя (сохраняются)

Это позволяет показывать пользователю полный контекст, но сохранять только релевантные данные.
