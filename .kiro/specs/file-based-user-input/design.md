# Design Document: File-Based User Input

## Overview

Данный документ описывает проектирование функциональности файлового ввода для Workflow Orchestrator. Функциональность позволяет пользователям вводить большие структурированные данные и отвечать на вопросы через текстовые файлы, которые автоматически открываются в редакторе, вместо использования командной строки.

Основные преимущества:
- Удобство работы с большими промптами и структурированными данными
- Возможность редактирования в привычном редакторе
- Сохранение прогресса и возможность возобновления
- Валидация данных перед продолжением выполнения
- Оптимизация контекста для снижения затрат на API

### Поток данных

1. **Создание шаблона**: FileInputHandler создает файл-шаблон с подсказками
2. **Открытие редактора**: EditorManager запускает редактор с файлом
3. **Приостановка**: Процесс приостанавливается, статус = 'paused'
4. **Ожидание**: Интерактивное меню с выбором стрелочками ожидает действия пользователя (по умолчанию "Продолжить")
5. **Чтение**: После подтверждения (Enter) читается заполненный файл
6. **Валидация**: UserInputHandler валидирует данные
7. **Обработка**: Данные обрабатываются и добавляются в контекст
8. **Продолжение**: Процесс возобновляется со следующего шага

## Components and Interfaces

### 1. FileInputHandler

Основной компонент для управления файловым вводом.

```typescript
/**
 * Обработчик файлового ввода пользователя
 */
export class FileInputHandler {
  private templateGenerator: TemplateGenerator;
  private editorManager: EditorManager;
  private userInputHandler: UserInputHandler;
  private logger: Logger;
  
  constructor(
    templateGenerator: TemplateGenerator,
    editorManager: EditorManager,
    userInputHandler: UserInputHandler,
    logger: Logger
  );
  
  /**
   * Обработка файлового ввода для шага
   * 
   * @param step - Шаг user_input
   * @param context - Контекст выполнения
   * @returns Promise<FileInputResult> - Результат обработки
   */
  async handleFileInput(
    step: WorkflowStep,
    context: ExecutionContext
  ): Promise<FileInputResult>;
  
  /**
   * Создание файла-шаблона
   * 
   * @param step - Шаг user_input
   * @param context - Контекст выполнения
   * @returns Promise<string> - Путь к созданному файлу
   */
  private async createTemplateFile(
    step: WorkflowStep,
    context: ExecutionContext
  ): Promise<string>;
  
  /**
   * Открытие файла в редакторе
   * 
   * @param filePath - Путь к файлу
   * @param editorConfig - Конфигурация редактора (опционально)
   * @returns Promise<void>
   */
  private async openInEditor(
    filePath: string,
    editorConfig?: EditorConfig
  ): Promise<void>;
  
  /**
   * Ожидание подтверждения от пользователя через интерактивное меню
   * 
   * @param filePath - Путь к файлу для редактирования
   * @returns Promise<UserCommand> - Команда пользователя (выбранная стрелочками)
   */
  private async waitForUserConfirmation(
    filePath: string
  ): Promise<UserCommand>;
  
  /**
   * Чтение и валидация заполненного файла
   * 
   * @param filePath - Путь к файлу
   * @param step - Шаг user_input
   * @param context - Контекст выполнения
   * @returns Promise<ParsedUserInput> - Распарсенные данные
   */
  private async readAndValidate(
    filePath: string,
    step: WorkflowStep,
    context: ExecutionContext
  ): Promise<ParsedUserInput>;
}
```

   */
  private generateYAMLTemplate(

   * Генерация JSON шаблона
   */
  private generateJSONTemplate(

### 3. EditorManager

Менеджер для работы с текстовыми редакторами.

```typescript
/**
 * Менеджер текстовых редакторов
 */
export class EditorManager {
  private logger: Logger;
  
  constructor(logger: Logger);
  
  /**
   * Запуск редактора с файлом
   * 
   * @param filePath - Путь к файлу
   * @param config - Конфигурация редактора (опционально)
   * @returns Promise<void>
   */
  async launchEditor(
    filePath: string,
    config?: EditorConfig
  ): Promise<void>;
  
  /**
   * Определение системного редактора по умолчанию
   * 
   * @returns Promise<string> - Команда для запуска редактора
   */
  async detectSystemEditor(): Promise<string>;
  
  /**
   * Проверка доступности редактора
   * 
   * @param editorCommand - Команда редактора
   * @returns Promise<boolean> - Доступен ли редактор
   */
  async checkEditorAvailability(
    editorCommand: string
  ): Promise<boolean>;
  
  /**
   * Получение списка популярных редакторов для платформы
   * 
   * @returns string[] - Список команд редакторов
   */
  private getCommonEditors(): string[];
}
```

## Correctness Properties

*Свойство (property) - это характеристика или поведение, которое должно выполняться для всех допустимых выполнений системы. Свойства служат мостом между человекочитаемыми спецификациями и машинно-проверяемыми гарантиями корректности.*

### Property 1: Создание валидного шаблона

*Для любого* шага user_input с режимом file, создание файла-шаблона должно производить валидный файл указанного формата с корректными инструкциями

**Validates: Requirements 1.1, 1.2, 1.3, 1.4, 1.5**

### Property 2: Открытие редактора

*Для любого* редактора, доступного на текущей платформе, попытка открыть файл должна успешно запустить редактор или вернуть понятную ошибку

**Validates: Requirements 2.1, 2.2, 2.3, 2.4**

### Property 3: Приостановка процесса с интерактивным меню

*Для любого* шага user_input с файловым вводом, после создания шаблона процесс должен перейти в статус 'paused' и отобразить интерактивное меню с выбором стрелочками

**Validates: Requirements 3.1, 3.2, 3.3, 3.4, 3.5**

### Property 4: Обработка выбора в интерактивном меню

*Для любого* выбора пользователя в интерактивном меню ("Продолжить" или "Отложить"), система должна корректно обработать выбор и выполнить соответствующее действие, при этом Enter без изменения выбора должен выполнить действие по умолчанию (продолжить)

**Validates: Requirements 3.4, 3.5, 3.6, 3.7**

### Property 5: Валидация ввода

*Для любого* заполненного файла, если данные не проходят валидацию, система должна вернуть конкретные ошибки и позволить повторное редактирование

**Validates: Requirements 4.1, 4.2, 4.3, 4.4, 4.5**

### Property 6: Сохранение в контекст

*Для любого* валидного ввода пользователя, данные должны быть корректно сохранены в контекст и доступны для следующих шагов

**Validates: Requirements 4.6**

### Property 7: Обработка вопросов

*Для любого* файла с вопросами и ответами, система должна корректно извлечь ответы и сопоставить их с вопросами

**Validates: Requirements 5.1, 5.2, 5.3, 5.4**

### Property 8: Оптимизация контекста

*Для любого* набора ответов, если include_questions = false, в контекст должны передаваться только ответы без текста вопросов

**Validates: Requirements 6.1, 6.2, 6.3, 6.4, 6.5**

### Property 9: Выбор режима ввода

*Для любого* шага user_input, если input_mode не указан, должен использоваться default_input_mode из настроек процесса или 'console' по умолчанию

**Validates: Requirements 7.1, 7.2, 7.3, 7.4, 7.5**

### Property 10: Возобновление процесса

*Для любого* приостановленного процесса с заполненным файлом, при возобновлении система должна загрузить данные и продолжить выполнение

**Validates: Requirements 8.1, 8.2, 8.3, 8.4, 8.5**

### Property 11: Поддержка форматов

*Для любого* поддерживаемого формата (markdown, yaml, json, text), система должна корректно генерировать шаблон и парсить заполненный файл

**Validates: Requirements 9.1, 9.2, 9.3, 9.4, 9.5**

### Property 12: Обработка ошибок создания файла

*Для любой* ошибки создания файла-шаблона, система должна вернуть понятное сообщение об ошибке и предложить альтернативный путь

**Validates: Requirements 10.1**

### Property 13: Обработка недоступного редактора

*Для любого* недоступного редактора, система должна вывести предупреждение и путь к файлу для ручного открытия, не прерывая процесс

**Validates: Requirements 10.2**

### Property 14: Обработка удаленного файла

*Для любого* случая, когда файл-шаблон был удален пользователем, система должна предложить создать новый файл

**Validates: Requirements 10.3**

### Property 15: Обработка некорректных данных

*Для любого* файла с некорректными данными, система должна вывести конкретные ошибки валидации с указанием полей и проблем

**Validates: Requirements 10.4**

### Property 16: Сохранение при прерывании

*Для любого* прерывания процесса во время редактирования, частично заполненный файл должен быть сохранен для возможности возобновления

**Validates: Requirements 10.5**

## Error Handling

### Категории ошибок

1. **Ошибки создания файла**
   - Недостаточно прав для записи
   - Недоступна директория артефактов
   - Ошибка генерации шаблона

2. **Ошибки редактора**
   - Редактор не найден
   - Ошибка запуска редактора
   - Редактор завершился с ошибкой

3. **Ошибки валидации**
   - Некорректный формат файла
   - Отсутствуют обязательные поля
   - Данные не соответствуют типу

4. **Ошибки состояния**
   - Файл был удален
   - Файл не был изменен
   - Процесс уже завершен

### Стратегии восстановления

```typescript
/**
 * Обработка ошибки создания файла
 */
if (error.code === 'FILE_CREATION_ERROR') {
  // 1. Попытка создать в альтернативной директории
  // 2. Предложение пользователю указать путь вручную
  // 3. Переключение на консольный ввод
}

/**
 * Обработка недоступного редактора
 */
if (error.code === 'EDITOR_NOT_AVAILABLE') {
  // 1. Попытка использовать альтернативный редактор
  // 2. Вывод пути к файлу для ручного открытия
  // 3. Продолжение в интерактивном режиме
}

/**
 * Обработка ошибок валидации
 */
if (error.code === 'VALIDATION_ERROR') {
  // 1. Вывод конкретных ошибок
  // 2. Предложение повторного редактирования
  // 3. Сохранение текущего состояния файла
}

/**
 * Обработка удаленного файла
 */
if (error.code === 'FILE_NOT_FOUND') {
  // 1. Проверка, был ли файл создан ранее
  // 2. Предложение создать новый файл
  // 3. Восстановление из резервной копии (если есть)
}
```

## Testing Strategy

### Unit Tests

Модульные тесты для проверки отдельных компонентов:

1. **TemplateGenerator**
   - Генерация шаблонов для каждого формата
   - Корректность структуры шаблона
   - Включение инструкций и подсказок
   - Извлечение вопросов из prompt_message

2. **EditorManager**
   - Определение системного редактора
   - Проверка доступности редактора
   - Формирование команды запуска
   - Обработка ошибок запуска

3. **FileInputHandler**
   - Создание файла-шаблона
   - Чтение и парсинг файла
   - Валидация данных
   - Обработка команд пользователя

4. **UserInputHandler (расширения)**
   - Извлечение только ответов
   - Форматирование для контекста
   - Оптимизация размера контекста

### Property-Based Tests

Тесты свойств для проверки корректности на множестве входных данных:

1. **Property 1: Создание валидного шаблона**
   - Генерация случайных конфигураций шагов
   - Проверка валидности созданных шаблонов
   - Проверка наличия всех обязательных элементов

2. **Property 5: Валидация ввода**
   - Генерация случайных данных (валидных и невалидных)
   - Проверка корректности валидации
   - Проверка сообщений об ошибках

3. **Property 7: Обработка вопросов**
   - Генерация случайных наборов вопросов и ответов
   - Проверка корректности сопоставления
   - Проверка обработки различных форматов ответов

4. **Property 8: Оптимизация контекста**
   - Генерация случайных ответов
   - Проверка размера контекста с/без вопросов
   - Проверка корректности данных

5. **Property 11: Поддержка форматов**
   - Генерация случайных данных для каждого формата
   - Проверка round-trip (генерация → парсинг → сравнение)
   - Проверка обработки специальных символов

### Integration Tests
