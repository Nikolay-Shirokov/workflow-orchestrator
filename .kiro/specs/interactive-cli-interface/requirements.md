# Требования: Интерактивный интерфейс CLI

## Введение

Данный документ описывает требования к интерактивному интерфейсу для консольной утилиты Workflow Orchestrator. Текущая реализация выводит информацию о выполнении в виде последовательного лога, что затрудняет отслеживание общего прогресса и состояния процесса. Новый интерфейс должен предоставить структурированное отображение с возможностью переключения между режимами.

## Глоссарий

- **CLI** - Command Line Interface, интерфейс командной строки
- **Workflow** - рабочий процесс, последовательность шагов для выполнения задачи
- **Step** - шаг рабочего процесса
- **Artifact** - артефакт, файл созданный в результате выполнения шага
- **Session** - сессия выполнения рабочего процесса
- **Interactive_Mode** - интерактивный режим отображения с обновляемым интерфейсом
- **Log_Mode** - режим последовательного вывода лога (текущая реализация)
- **Progress_Display** - компонент отображения прогресса выполнения
- **Terminal_UI** - пользовательский интерфейс в терминале

## Требования

### Requirement 1: Режимы отображения

**User Story:** Как пользователь, я хочу выбирать между интерактивным и логовым режимами отображения, чтобы использовать наиболее удобный для моей ситуации интерфейс.

#### Acceptance Criteria

1. THE System SHALL поддерживать два режима отображения: интерактивный (по умолчанию) и логовый
2. WHEN пользователь запускает процесс с флагом `--log-mode`, THE System SHALL использовать логовый режим отображения
3. WHEN пользователь запускает процесс без флага `--log-mode`, THE System SHALL использовать интерактивный режим отображения
4. THE System SHALL сохранять выбранный режим отображения на протяжении всей сессии выполнения

### Requirement 2: Интерактивный режим - Структура отображения

**User Story:** Как пользователь, я хочу видеть структурированную информацию о выполнении процесса, чтобы быстро понимать текущее состояние и прогресс.

#### Acceptance Criteria

1. WHEN процесс выполняется в интерактивном режиме, THE Terminal_UI SHALL отображать следующие секции:
   - Заголовок с названием процесса и версией
   - Путь к директории артефактов
   - Список всех шагов с их статусами
   - Секцию с последними действиями (последние 2-3 шага)
   - Общий прогресс выполнения

2. THE Terminal_UI SHALL обновлять отображение на месте без прокрутки терминала

3. THE Terminal_UI SHALL использовать цветовую индикацию для статусов:
   - Зеленый для завершенных шагов
   - Желтый для текущего шага
   - Серый для ожидающих шагов
   - Красный для ошибок

### Requirement 3: Отображение списка шагов

**User Story:** Как пользователь, я хочу видеть список всех шагов процесса с их статусами, чтобы понимать общую картину выполнения.

#### Acceptance Criteria

1. WHEN процесс выполняется, THE Terminal_UI SHALL отображать список всех шагов в формате:
   - Номер шага
   - Иконка статуса (✓ завершен, ⏳ выполняется, ○ ожидает, ✗ ошибка)
   - Название шага
   - ID шага

2. THE Terminal_UI SHALL выделять текущий выполняемый шаг визуально

3. WHEN шаг завершается, THE Terminal_UI SHALL обновлять его статус в списке

### Requirement 4: Информация о текущем шаге

**User Story:** Как пользователь, я хочу видеть детальную информацию о текущем выполняемом шаге, чтобы понимать, что происходит в данный момент.

#### Acceptance Criteria

1. WHEN шаг выполняется, THE Terminal_UI SHALL отображать:
   - Название и ID шага
   - Тип шага
   - Используемую роль (если применимо)
   - Используемый адаптер (если применимо)
   - Используемую модель (если применимо)
   - Время выполнения

2. WHEN шаг создает артефакты, THE Terminal_UI SHALL отображать список созданных артефактов

3. WHEN шаг завершается с ошибкой, THE Terminal_UI SHALL отображать сообщение об ошибке

### Requirement 5: История последних действий

**User Story:** Как пользователь, я хочу видеть последние выполненные действия, чтобы понимать ход выполнения процесса.

#### Acceptance Criteria

1. THE Terminal_UI SHALL отображать последние 2-3 завершенных шага

2. WHEN новый шаг завершается, THE Terminal_UI SHALL добавлять его в историю и удалять самый старый

3. THE Terminal_UI SHALL отображать для каждого шага в истории:
   - Название шага
   - Статус (успех/ошибка)
   - Время выполнения
   - Количество созданных артефактов

### Requirement 6: Общий прогресс

**User Story:** Как пользователь, я хочу видеть общий прогресс выполнения процесса, чтобы оценивать оставшееся время.

#### Acceptance Criteria

1. THE Terminal_UI SHALL отображать индикатор прогресса в виде прогресс-бара

2. THE Terminal_UI SHALL отображать процент выполнения (завершенные шаги / общее количество шагов)

3. THE Terminal_UI SHALL отображать количество завершенных шагов и общее количество шагов

4. THE Terminal_UI SHALL отображать общее время выполнения процесса

### Requirement 7: Логовый режим (обратная совместимость)

**User Story:** Как пользователь, я хочу иметь возможность использовать традиционный логовый режим, чтобы сохранять вывод в файл или использовать в скриптах.

#### Acceptance Criteria

1. WHEN процесс запущен с флагом `--log-mode`, THE System SHALL использовать текущую реализацию Progress_Display

2. THE System SHALL выводить информацию последовательно без обновления на месте

3. THE System SHALL сохранять всю функциональность текущей реализации

### Requirement 8: Обработка изменения размера терминала

**User Story:** Как пользователь, я хочу, чтобы интерфейс корректно адаптировался при изменении размера терминала, чтобы информация оставалась читаемой.

#### Acceptance Criteria

1. WHEN размер терминала изменяется, THE Terminal_UI SHALL перерисовывать интерфейс с учетом новых размеров

2. THE Terminal_UI SHALL корректно обрабатывать узкие терминалы (минимальная ширина 60 символов)

3. WHEN терминал слишком узкий, THE Terminal_UI SHALL отображать предупреждение и переключаться в упрощенный режим

### Requirement 9: Параллельное выполнение

**User Story:** Как пользователь, я хочу видеть информацию о параллельно выполняемых шагах, чтобы понимать, какие задачи выполняются одновременно.

#### Acceptance Criteria

1. WHEN несколько шагов выполняются параллельно, THE Terminal_UI SHALL отображать их все в секции текущих шагов

2. THE Terminal_UI SHALL группировать параллельные шаги визуально

3. THE Terminal_UI SHALL отображать индикатор параллельного выполнения (⚡)

### Requirement 10: Ввод пользователя

**User Story:** Как пользователь, я хочу, чтобы интерфейс корректно обрабатывал паузы для ввода данных, чтобы я мог взаимодействовать с процессом.

#### Acceptance Criteria

1. WHEN требуется ввод пользователя, THE Terminal_UI SHALL отображать специальное сообщение с инструкциями

2. THE Terminal_UI SHALL временно приостанавливать обновление интерфейса во время ввода

3. WHEN ввод завершен, THE Terminal_UI SHALL возобновлять обновление интерфейса

### Requirement 10.1: Интерактивное меню

**User Story:** Как пользователь, я хочу использовать интерактивное меню для управления процессом, чтобы выбирать действия без ввода команд.

#### Acceptance Criteria

1. WHEN требуется выбор пользователя, THE Terminal_UI SHALL отображать интерактивное меню с опциями

2. THE Terminal_UI SHALL поддерживать навигацию по меню с помощью стрелок вверх/вниз

3. WHEN пользователь выбирает опцию, THE Terminal_UI SHALL перерисовывать интерфейс с учетом выбора

4. THE Terminal_UI SHALL отображать меню на том же экране, что и список шагов

5. THE Terminal_UI SHALL выделять текущую выбранную опцию визуально

### Requirement 11: Завершение процесса

**User Story:** Как пользователь, я хочу видеть итоговую информацию после завершения процесса, чтобы оценить результаты выполнения.

#### Acceptance Criteria

1. WHEN процесс завершается, THE Terminal_UI SHALL отображать итоговую информацию:
   - Статус завершения (успех/ошибка)
   - Общее время выполнения
   - Количество завершенных шагов
   - Количество созданных артефактов
   - ID сессии

2. THE Terminal_UI SHALL сохранять итоговую информацию на экране после завершения

3. WHEN процесс завершается с ошибками, THE Terminal_UI SHALL отображать список ошибок

### Requirement 12: Автоматическое открытие результатов

**User Story:** Как пользователь, я хочу, чтобы основной выходной документ автоматически открывался после завершения процесса, чтобы сразу увидеть результаты работы.

#### Acceptance Criteria

1. WHEN процесс завершается успешно И существует основной выходной документ, THE System SHALL предложить открыть его в редакторе

2. THE System SHALL определять основной выходной документ как последний созданный артефакт с расширением .md, .txt, .yaml или .json

3. WHEN пользователь подтверждает открытие, THE System SHALL открывать документ в настроенном редакторе

4. WHEN редактор не настроен, THE System SHALL использовать системный редактор по умолчанию

5. THE System SHALL поддерживать флаг `--no-open` для отключения автоматического открытия

### Requirement 13: Компактный вывод тестов

**User Story:** Как разработчик, я хочу видеть компактный вывод при запуске тестов, чтобы не тратить контекстное окно на избыточную информацию.

#### Acceptance Criteria

1. WHEN тесты запускаются, THE System SHALL выводить детальную информацию только для упавших тестов

2. WHEN тест проходит успешно, THE System SHALL выводить только краткую информацию (имя теста и статус)

3. WHEN тест падает, THE System SHALL выводить полную информацию: имя теста, ошибку, stack trace, входные данные (для property-based тестов)

4. THE System SHALL выводить итоговую статистику: общее количество тестов, пройденные, упавшие, пропущенные, время выполнения

5. THE System SHALL поддерживать флаг `--verbose` для вывода детальной информации по всем тестам

### Requirement 14: Интерактивное возобновление процесса

**User Story:** Как пользователь, я хочу выбирать шаг, с которого возобновить процесс, чтобы перезапустить выполнение с нужного места.

#### Acceptance Criteria

1. WHEN пользователь запускает команду `resume`, THE System SHALL отображать интерактивный список всех шагов процесса

2. THE System SHALL отображать для каждого шага:
   - Номер шага
   - Название шага
   - Статус выполнения (✓ завершен, ○ не выполнен)
   - Наличие артефактов

3. THE System SHALL автоматически позиционировать курсор на первом незавершенном шаге

4. THE System SHALL позволять пользователю изменить выбор с помощью стрелок вверх/вниз

5. WHEN пользователь подтверждает выбор (Enter), THE System SHALL инициализировать процесс артефактами всех предыдущих шагов

6. THE System SHALL игнорировать артефакты выбранного и последующих шагов

7. THE System SHALL начинать выполнение с выбранного шага
