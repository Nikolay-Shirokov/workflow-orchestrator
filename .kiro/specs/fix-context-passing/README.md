# Спецификация: Исправление передачи контекста между шагами

## Краткое описание

Эта спецификация описывает исправление критической проблемы с передачей контекста между шагами workflow, когда вложенные подстановки переменных в шаблонах промптов не работают корректно.

## Проблема

В текущей реализации:
1. Шаг создает артефакт и добавляет переменную `output_name_file` с путем к файлу
2. Следующий шаг использует `${artifact:${output_name_file}}` в промпте
3. Template-engine не может разрешить вложенную переменную
4. В промпт попадает буквальный текст вместо содержимого файла

## Решение

### 1. Двойная передача контекста

Каждый артефакт теперь доступен двумя способами:
- `output_name` - содержимое артефакта (быстро, в памяти)
- `output_name_file` - путь к файлу (для явной загрузки)

### 2. Улучшенная обработка вложенных подстановок

Template-engine корректно разрешает `${artifact:${variable}}`:
1. Сначала разрешает `${variable}` в путь
2. Затем загружает содержимое из файла
3. Кэширует результат на 5 минут

### 3. Опциональное обрамление в теги

Новый синтаксис `${artifact:${variable}:tag_name}` обрамляет содержимое:
```markdown
<tag_name>
[содержимое артефакта]
</tag_name>
```

Помогает AI-модели различать границы вложенных данных.

## Три способа использования

### Способ 1: Прямое содержимое (РЕКОМЕНДУЕТСЯ)
```markdown
${architect_questions}
```
- ✅ Самый быстрый
- ✅ Простой синтаксис
- ✅ Нет операций I/O

### Способ 2: Загрузка с тегами
```markdown
${artifact:${architect_questions_file}:questions}
```
- ✅ Четкие границы для AI
- ✅ Структурированность
- ✅ Полезно для сложных промптов

### Способ 3: Загрузка без тегов
```markdown
${artifact:${architect_questions_file}}
```
- ✅ Гарантия актуальности
- ✅ Экономия памяти
- ✅ Для больших артефактов

## Файлы спецификации

- **requirements.md** - Детальные требования с acceptance criteria
- **design.md** - Архитектура решения и correctness properties
- **tasks.md** - План реализации с задачами
- **PROMPT_MIGRATION.md** - Руководство по обновлению промптов

## Ключевые преимущества

1. **Производительность**: +30-50% за счет прямой передачи содержимого
2. **Гибкость**: Три способа использования для разных сценариев
3. **Надежность**: Корректная обработка вложенных подстановок
4. **Обратная совместимость**: Существующие workflow работают без изменений
5. **Структурированность**: Теги помогают AI различать вложенные данные

## Следующие шаги

1. Просмотреть requirements.md для понимания всех требований
2. Изучить design.md для понимания архитектуры решения
3. Следовать tasks.md для пошаговой реализации
4. Использовать PROMPT_MIGRATION.md для обновления промптов
