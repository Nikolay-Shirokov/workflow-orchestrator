# Интеграция с MCP (Model Context Protocol)

## Обзор

Workflow Orchestrator поддерживает интеграцию с MCP-инструментами, что позволяет:

- Проверять доступность MCP-инструментов перед выполнением процесса
- Условно выполнять шаги на основе доступности инструментов
- Автоматически передавать информацию о доступных инструментах в контекст модели
- Логировать предупреждения о недоступных инструментах

## Конфигурация MCP-инструментов

MCP-инструменты настраиваются в секции `settings.mcp_tools` конфигурации рабочего процесса:

```yaml
settings:
  mcp_tools:
    - name: "web_search"              # Имя инструмента
      checkCommand: "which mcp-web"   # Команда для проверки доступности
      expectedExitCode: 0             # Ожидаемый код выхода (по умолчанию 0)
      timeout: 5000                   # Таймаут проверки в мс (по умолчанию 5000)
      required: false                 # Обязателен ли инструмент (по умолчанию false)
```

### Параметры конфигурации

- **name** (обязательный): Уникальное имя инструмента
- **checkCommand** (опциональный): Команда для проверки доступности. Если не указана, инструмент считается доступным
- **expectedExitCode** (опциональный): Ожидаемый код выхода команды проверки (по умолчанию 0)
- **timeout** (опциональный): Таймаут выполнения команды проверки в миллисекундах (по умолчанию 5000)
- **required** (опциональный): Если `true`, процесс завершится с ошибкой при недоступности инструмента (по умолчанию false)

## Условное выполнение шагов

Шаги могут быть настроены для условного выполнения на основе доступности MCP-инструментов:

```yaml
steps:
  - id: "web_research"
    name: "Веб-исследование"
    type: "model"
    # Выполняется только если web_search доступен
    condition: "mcp_tools.web_search_available"
    prompt_template: "prompts/web_research.txt"
```

### Доступные условия

Для каждого инструмента автоматически создается флаг доступности в формате `{tool_name}_available`:

- `mcp_tools.web_search_available` - доступен ли web_search
- `mcp_tools.file_access_available` - доступен ли file_access
- и т.д.

Также доступны специальные условия:

- `any_mcp_available` - доступен ли хотя бы один MCP-инструмент
- `all_mcp_available` - доступны ли все MCP-инструменты

## Автоматическая передача информации в промпт

Информация о доступных и недоступных MCP-инструментах автоматически добавляется в промпт для каждого шага типа `model`:

```
[Ваш промпт]

---

Доступные MCP-инструменты:
  - web_search: Поиск в интернете
  - file_access: Доступ к файлам

Недоступные MCP-инструменты:
  - database: Работа с базой данных
```

Это позволяет модели знать, какие инструменты она может использовать.

## Логирование

MCPManager автоматически логирует:

- Процесс проверки доступности инструментов
- Результаты проверки (доступен/недоступен)
- Предупреждения о недоступных инструментах
- Ошибки при проверке обязательных инструментов

Пример логов:

```
[INFO] Проверка доступности MCP-инструментов...
[INFO] MCP-инструмент web_search доступен
[WARN] MCP-инструмент database недоступен
[INFO] MCP-инструменты: 2 доступно, 1 недоступно
[WARN] Обнаружено 1 недоступных MCP-инструментов:
[WARN]   - database: Работа с базой данных
[WARN] Шаги, зависящие от этих инструментов, могут быть пропущены
```

## Кэширование

MCPManager кэширует результаты проверки доступности инструментов на 1 минуту, чтобы избежать повторных проверок при возобновлении процесса.

Кэш можно очистить вручную:

```typescript
mcpManager.clearCache();
```

## API

### MCPManager

```typescript
class MCPManager {
  // Проверка доступности одного инструмента
  async checkToolAvailability(config: MCPToolConfig): Promise<MCPToolInfo>
  
  // Проверка доступности нескольких инструментов
  async checkMultipleTools(configs: MCPToolConfig[]): Promise<MCPToolInfo[]>
  
  // Создание контекста MCP для передачи в модель
  createMCPContext(tools: MCPToolInfo[]): MCPContext
  
  // Оценка условия на основе доступности MCP
  evaluateCondition(condition: string, mcpContext: MCPContext): boolean
  
  // Логирование недоступных инструментов
  logUnavailableTools(tools: MCPToolInfo[], stepId?: string): void
  
  // Форматирование информации для промпта
  formatForPrompt(mcpContext: MCPContext): string
  
  // Очистка кэша
  clearCache(): void
  
  // Получение информации из кэша
  getCachedToolInfo(toolName: string): MCPToolInfo | undefined
}
```

### Типы

```typescript
interface MCPToolConfig {
  name: string;
  checkCommand?: string;
  expectedExitCode?: number;
  timeout?: number;
  required?: boolean;
}

interface MCPToolInfo {
  name: string;
  description: string;
  available: boolean;
  version?: string;
  metadata?: Record<string, unknown>;
}

interface MCPContext {
  available_tools: string[];
  unavailable_tools: string[];
  tools: Record<string, MCPToolInfo>;
  flags: Record<string, boolean>;
}
```

## Требования

Реализация соответствует следующим требованиям из спецификации:

- **18.1**: Проверка доступности MCP-инструментов при инициализации процесса
- **18.2**: Условное выполнение шагов на основе доступности MCP
- **18.3**: Передача информации о доступных инструментах в контекст модели
- **18.4**: Автоматическое определение необходимости инструментов
- **18.5**: Логирование предупреждений при недоступности MCP

## Ограничения

- Проверка доступности выполняется только при запуске/возобновлении процесса
- Кэш результатов проверки действителен 1 минуту
- Команды проверки должны завершаться быстро (таймаут по умолчанию 5 секунд)
- Информация о MCP добавляется в конец промпта автоматически
