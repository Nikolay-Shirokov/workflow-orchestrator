# Руководство по передаче контекста между шагами

## Обзор

Workflow Orchestrator поддерживает несколько способов передачи данных между шагами workflow. Этот документ поможет выбрать оптимальный подход для вашего случая.

## Три способа передачи контекста

### 1. Прямое содержимое (рекомендуется по умолчанию)

**Синтаксис:**
```yaml
prompt_template: |
  Используйте данные:
  ${variable_name}
```

**Как работает:**
- Когда шаг создает артефакт с именем `output_name`, содержимое автоматически сохраняется в контексте
- Переменная `${output_name}` содержит полное содержимое артефакта
- Нет операций чтения файла - данные уже в памяти

**Преимущества:**
- ⚡ Самый быстрый способ (~1мс)
- 📝 Простой и понятный синтаксис
- 💾 Минимальные операции I/O
- ✅ Рекомендуется для большинства случаев

**Когда использовать:**
- Для outputs предыдущих шагов
- Для данных размером < 100KB
- Когда не нужно явное разграничение
- Для простого текста

**Пример:**
```yaml
steps:
  - id: "analysis"
    outputs:
      result: "${artifacts_dir}/analysis.md"
  
  - id: "summary"
    depends_on: ["analysis"]
    prompt_template: |
      Создайте краткое резюме:
      ${result}
```

### 2. Загрузка из файла

**Синтаксис:**
```yaml
prompt_template: |
  Используйте данные из файла:
  ${artifact:${variable_name_file}}
```

**Как работает:**
- Система автоматически создает переменную `${output_name_file}` с путем к файлу
- При использовании `${artifact:${path}}` содержимое загружается из файла
- Результат кэшируется на 5 минут

**Преимущества:**
- ✅ Гарантирует актуальность данных
- 💾 Экономит память (не хранит в контексте)
- 🔄 Полезно для внешних изменений
- ⚡ Кэширование ускоряет повторные загрузки

**Когда использовать:**
- Файл может быть изменен внешним процессом
- Данные слишком большие для хранения в памяти (> 100KB)
- Нужна гарантия актуальности
- Работа с внешними артефактами

**Пример:**
```yaml
steps:
  - id: "analysis"
    outputs:
      result: "${artifacts_dir}/analysis.md"
  
  - id: "summary"
    depends_on: ["analysis"]
    prompt_template: |
      Создайте краткое резюме из файла:
      ${artifact:${result_file}}
```

### 3. Загрузка с обрамлением в теги

**Синтаксис:**
```yaml
prompt_template: |
  Используйте данные:
  ${artifact:${variable_name_file}:tag_name}
```

**Как работает:**
- Загружает содержимое из файла
- Обрамляет в XML-подобные теги: `<tag_name>...</tag_name>`
- Помогает AI-модели различать границы данных

**Преимущества:**
- 🏷️ Четкие границы для AI-модели
- 📊 Идеально для больших данных
- 🔀 Упрощает работу с множественными артефактами
- 📋 Отлично для структурированных данных

**Когда использовать:**
- Большие объемы данных (> 1000 символов)
- Несколько артефактов в одном промпте
- Структурированные данные (JSON, YAML, код)
- Когда нужны четкие границы для AI

**Пример:**
```yaml
steps:
  - id: "parallel_analysis"
    type: "parallel"
    steps:
      - id: "technical"
        outputs:
          tech: "${artifacts_dir}/technical.md"
      - id: "business"
        outputs:
          biz: "${artifacts_dir}/business.md"
  
  - id: "merge"
    depends_on: ["parallel_analysis"]
    prompt_template: |
      Объедините анализы:
      
      ## Технический
      ${artifact:${tech_file}:technical}
      
      ## Бизнес
      ${artifact:${biz_file}:business}
```

**Результат:**
```
Объедините анализы:

## Технический
<technical>
[содержимое технического анализа]
</technical>

## Бизнес
<business>
[содержимое бизнес-анализа]
</business>
```

## Рекомендации по выбору

### Используйте прямое содержимое когда:
- ✅ Это outputs предыдущих шагов
- ✅ Размер данных < 100KB
- ✅ Не нужно явное разграничение
- ✅ Простой текст без сложной структуры
- ✅ Хотите максимальную производительность

### Используйте загрузку из файла когда:
- ✅ Файл может быть изменен внешним процессом
- ✅ Данные слишком большие (> 100KB)
- ✅ Нужна гарантия актуальности
- ✅ Работаете с внешними артефактами

### Используйте теги когда:
- ✅ Большие объемы данных (> 1000 символов)
- ✅ Несколько артефактов в одном промпте
- ✅ Структурированные данные (JSON, YAML, XML, код)
- ✅ Нужны четкие границы для AI-модели
- ✅ Вложенные уровни данных

## Примеры из практики

### Пример 1: Простой анализ (прямое содержимое)

```yaml
steps:
  - id: "requirements"
    outputs:
      reqs: "${artifacts_dir}/requirements.md"
  
  - id: "analysis"
    depends_on: ["requirements"]
    prompt_template: |
      Проанализируйте требования:
      ${reqs}
```

**Почему:** Данные небольшие, уже в памяти, не нужны теги.

### Пример 2: Большой документ (с тегами)

```yaml
steps:
  - id: "research"
    outputs:
      research: "${artifacts_dir}/research.md"
  
  - id: "summary"
    depends_on: ["research"]
    prompt_template: |
      Создайте краткое резюме исследования:
      
      ${artifact:${research_file}:research_data}
      
      Выделите ключевые моменты.
```

**Почему:** Большой объем данных, теги помогают AI различать границы.

### Пример 3: Множественные источники (с тегами)

```yaml
steps:
  - id: "gather"
    type: "parallel"
    steps:
      - id: "tech"
        outputs:
          tech: "${artifacts_dir}/tech.md"
      - id: "biz"
        outputs:
          biz: "${artifacts_dir}/biz.md"
      - id: "ux"
        outputs:
          ux: "${artifacts_dir}/ux.md"
  
  - id: "merge"
    depends_on: ["gather"]
    prompt_template: |
      Объедините все анализы:
      
      ${artifact:${tech_file}:technical}
      ${artifact:${biz_file}:business}
      ${artifact:${ux_file}:user_experience}
      
      Создайте единый документ.
```

**Почему:** Три источника данных, теги четко разграничивают каждый.

### Пример 4: Внешний файл (загрузка)

```yaml
steps:
  - id: "process"
    prompt_template: |
      Обработайте данные из внешнего файла:
      ${artifact:${external_data_path}}
    inputs:
      external_data_path: "${external_file}"
```

**Почему:** Файл может быть обновлен внешним процессом.

## Производительность

### Измерения

```
Прямое содержимое:     ~1мс   (данные в памяти)
Загрузка (кэш):       ~10мс   (из кэша)
Загрузка (файл):      ~50мс   (чтение файла)
С тегами (кэш):       ~12мс   (кэш + обрамление)
С тегами (файл):      ~52мс   (файл + обрамление)
```

### Кэширование

- Артефакты кэшируются на 5 минут
- Повторная загрузка использует кэш
- Кэш автоматически инвалидируется при изменении файла

### Оптимизация

**Для максимальной производительности:**
1. Используйте прямое содержимое для outputs шагов
2. Используйте теги только для больших данных
3. Полагайтесь на кэширование для повторных загрузок

**Для минимального использования памяти:**
1. Используйте загрузку из файла
2. Не храните большие данные в контексте
3. Полагайтесь на кэширование

## Миграция существующих workflow

### Старый синтаксис (медленнее)

```yaml
prompt_template: |
  ${artifact:${output_file}}
```

### Новый синтаксис (быстрее)

```yaml
prompt_template: |
  ${output}
```

**Обратная совместимость:** Старый синтаксис продолжает работать, но новый быстрее.

## Отладка

### Логирование

Включите DEBUG логирование для отслеживания загрузок:

```yaml
settings:
  log_level: "debug"
```

Вы увидите:
```
[DEBUG] Разрешение переменной: output
[DEBUG] Найдено в контексте: output (1234 символов)
[DEBUG] Загрузка артефакта: /path/to/file.md
[DEBUG] Кэш попадание: /path/to/file.md
[DEBUG] Обрамление в теги: data_tag
```

### Проверка контекста

Используйте dry-run для проверки контекста:

```bash
workflow-orchestrator dry-run workflow.yaml --verbose
```

## Часто задаваемые вопросы

**Q: Какой способ самый быстрый?**
A: Прямое содержимое (`${variable}`) - ~1мс vs ~50мс для загрузки из файла.

**Q: Когда использовать теги?**
A: Для больших данных (> 1000 символов) или множественных артефактов в одном промпте.

**Q: Работает ли старый синтаксис?**
A: Да, полная обратная совместимость. Но новый синтаксис быстрее.

**Q: Как работает кэширование?**
A: Артефакты кэшируются на 5 минут. Повторная загрузка использует кэш.

**Q: Можно ли комбинировать подходы?**
A: Да! Используйте разные подходы для разных данных в одном промпте.

**Q: Что если файл изменился?**
A: Используйте загрузку из файла (`${artifact:${path}}`) для гарантии актуальности.

**Q: Как выбрать имя тега?**
A: Используйте осмысленные имена (questions, analysis, code). Только буквы, цифры, дефисы и подчеркивания.

**Q: Влияют ли теги на AI-модель?**
A: Да, теги помогают модели четко различать границы разных частей данных.
