# Руководство по выбору способа передачи данных

## Быстрый выбор

Используйте эту блок-схему для выбора оптимального способа передачи данных:

```
┌─────────────────────────────────────┐
│ Это output предыдущего шага?        │
└──────────────┬──────────────────────┘
               │
        ┌──────┴──────┐
        │ ДА          │ НЕТ
        │             │
        ▼             ▼
┌───────────────┐  ┌──────────────────────────┐
│ Размер > 1KB? │  │ Файл может измениться?   │
└───────┬───────┘  └────────┬─────────────────┘
        │                   │
   ┌────┴────┐         ┌────┴────┐
   │ ДА      │ НЕТ     │ ДА      │ НЕТ
   │         │         │         │
   ▼         ▼         ▼         ▼
┌─────┐  ┌─────┐  ┌─────┐  ┌─────┐
│ С   │  │ Пря-│  │ Заг-│  │ Пря-│
│ тега│  │ мое │  │ рузка│  │ мой │
│ ми  │  │     │  │ из  │  │ путь│
└─────┘  └─────┘  │ файла│  └─────┘
                  └─────┘
```

## Три способа передачи данных

### 1. Прямое содержимое ⚡ (рекомендуется по умолчанию)

**Синтаксис:**
```yaml
${variable_name}
```

**Когда использовать:**
- ✅ Output предыдущего шага
- ✅ Размер < 1KB
- ✅ Простой текст
- ✅ Не нужны теги

**Производительность:** ~1мс

**Пример:**
```yaml
prompt_template: |
  Проанализируйте требования:
  ${requirements}
```

---

### 2. Загрузка из файла 📁

**Синтаксис:**
```yaml
${artifact:${variable_name_file}}
```

**Когда использовать:**
- ✅ Файл может быть изменен внешним процессом
- ✅ Нужна гарантия актуальности
- ✅ Размер > 100KB
- ✅ Экономия памяти

**Производительность:** ~10-50мс (с кэшем ~10мс)

**Пример:**
```yaml
prompt_template: |
  Проанализируйте данные из файла:
  ${artifact:${external_data_file}}
```

---

### 3. Загрузка с тегами 🏷️

**Синтаксис:**
```yaml
${artifact:${variable_name_file}:tag_name}
```

**Когда использовать:**
- ✅ Размер > 1KB
- ✅ Несколько артефактов в одном промпте
- ✅ Структурированные данные (JSON, YAML, код)
- ✅ Нужны четкие границы для AI

**Производительность:** ~12-52мс (с кэшем ~12мс)

**Пример:**
```yaml
prompt_template: |
  Объедините анализы:
  
  ${artifact:${tech_file}:technical}
  ${artifact:${biz_file}:business}
```

## Практические примеры

### Сценарий 1: Простой анализ

**Задача:** Проанализировать требования из предыдущего шага

**Решение:** Прямое содержимое
```yaml
prompt_template: |
  Проанализируйте требования:
  ${requirements}
```

**Почему:** Данные уже в памяти, небольшой размер, не нужны теги.

---

### Сценарий 2: Большой документ

**Задача:** Обработать большой документ исследования (> 10KB)

**Решение:** Загрузка с тегами
```yaml
prompt_template: |
  Создайте резюме исследования:
  
  ${artifact:${research_file}:research_data}
  
  Выделите ключевые моменты.
```

**Почему:** Большой объем данных, теги помогают AI различать границы.

---

### Сценарий 3: Множественные источники

**Задача:** Объединить три разных анализа

**Решение:** Загрузка с тегами
```yaml
prompt_template: |
  Объедините анализы:
  
  ${artifact:${tech_file}:technical}
  ${artifact:${biz_file}:business}
  ${artifact:${ux_file}:user_experience}
```

**Почему:** Три источника, теги четко разграничивают каждый.

---

### Сценарий 4: Внешний файл

**Задача:** Обработать файл, который может быть обновлен внешним процессом

**Решение:** Загрузка из файла
```yaml
prompt_template: |
  Обработайте данные:
  ${artifact:${external_file}}
```

**Почему:** Гарантия актуальности данных.

---

### Сценарий 5: Комбинированный подход

**Задача:** Использовать разные типы данных в одном промпте

**Решение:** Комбинация подходов
```yaml
prompt_template: |
  ## Запрос пользователя (прямое содержимое)
  ${user_request}
  
  ## Детальное исследование (с тегами)
  ${artifact:${research_file}:research}
  
  ## Краткие заметки (прямое содержимое)
  ${notes}
```

**Почему:** Каждый тип данных использует оптимальный способ передачи.

## Правила выбора

### Используйте прямое содержимое когда:

1. ✅ Данные из output предыдущего шага
2. ✅ Размер < 1KB
3. ✅ Простой текст без сложной структуры
4. ✅ Не нужно явное разграничение
5. ✅ Хотите максимальную производительность

**Пример:**
```yaml
${analysis}
${requirements}
${summary}
```

---

### Используйте загрузку из файла когда:

1. ✅ Файл может быть изменен внешним процессом
2. ✅ Размер > 100KB
3. ✅ Нужна гарантия актуальности
4. ✅ Хотите экономить память
5. ✅ Работаете с внешними артефактами

**Пример:**
```yaml
${artifact:${external_data_file}}
${artifact:${large_report_file}}
```

---

### Используйте теги когда:

1. ✅ Размер > 1KB
2. ✅ Несколько артефактов в одном промпте
3. ✅ Структурированные данные (JSON, YAML, XML, код)
4. ✅ Нужны четкие границы для AI-модели
5. ✅ Вложенные уровни данных

**Пример:**
```yaml
${artifact:${tech_file}:technical}
${artifact:${biz_file}:business}
${artifact:${code_file}:source_code}
```

## Оптимизация производительности

### Измерения

```
Прямое содержимое:     ~1мс   (данные в памяти)
Загрузка (кэш):       ~10мс   (из кэша)
Загрузка (файл):      ~50мс   (чтение файла)
С тегами (кэш):       ~12мс   (кэш + обрамление)
С тегами (файл):      ~52мс   (файл + обрамление)
```

### Рекомендации

**Для максимальной производительности:**
1. Используйте прямое содержимое для outputs шагов
2. Используйте теги только для больших данных
3. Полагайтесь на кэширование для повторных загрузок

**Для минимального использования памяти:**
1. Используйте загрузку из файла
2. Не храните большие данные в контексте
3. Полагайтесь на кэширование

**Для лучшего качества AI:**
1. Используйте теги для структурированных данных
2. Используйте теги для множественных артефактов
3. Используйте осмысленные имена тегов

## Частые ошибки

### ❌ Ошибка 1: Избыточная загрузка

```yaml
# Плохо: загрузка из файла для output шага
prompt_template: |
  ${artifact:${result_file}}
```

```yaml
# Хорошо: прямое содержимое
prompt_template: |
  ${result}
```

---

### ❌ Ошибка 2: Отсутствие тегов для больших данных

```yaml
# Плохо: без тегов сложно для AI
prompt_template: |
  ${artifact:${large_file1}}
  ${artifact:${large_file2}}
  ${artifact:${large_file3}}
```

```yaml
# Хорошо: с тегами четко разграничено
prompt_template: |
  ${artifact:${large_file1}:data1}
  ${artifact:${large_file2}:data2}
  ${artifact:${large_file3}:data3}
```

---

### ❌ Ошибка 3: Игнорирование кэширования

```yaml
# Плохо: каждый раз читает файл
prompt_template: |
  ${artifact:artifacts/data.md}
  ${artifact:artifacts/data.md}
  ${artifact:artifacts/data.md}
```

```yaml
# Хорошо: использует кэш
prompt_template: |
  ${artifact:${data_file}}  # Первая загрузка
  ${artifact:${data_file}}  # Из кэша
  ${artifact:${data_file}}  # Из кэша
```

---

### ❌ Ошибка 4: Неосмысленные имена тегов

```yaml
# Плохо: непонятные имена
prompt_template: |
  ${artifact:${file1}:data1}
  ${artifact:${file2}:data2}
```

```yaml
# Хорошо: осмысленные имена
prompt_template: |
  ${artifact:${tech_file}:technical_analysis}
  ${artifact:${biz_file}:business_requirements}
```

## Миграция существующих workflow

### Шаг 1: Идентифицируйте паттерны

Найдите все использования `${artifact:...}` в ваших промптах.

### Шаг 2: Определите тип данных

Для каждого использования определите:
- Это output предыдущего шага?
- Какой размер данных?
- Нужны ли теги?

### Шаг 3: Примените оптимизацию

**Было:**
```yaml
prompt_template: |
  ${artifact:${result_file}}
```

**Стало:**
```yaml
prompt_template: |
  ${result}  # Быстрее!
```

### Шаг 4: Добавьте теги где нужно

**Было:**
```yaml
prompt_template: |
  ${artifact:${large_file}}
```

**Стало:**
```yaml
prompt_template: |
  ${artifact:${large_file}:data}  # Четче для AI!
```

## Чек-лист для review

При review workflow конфигурации проверьте:

- [ ] Используется прямое содержимое для outputs шагов
- [ ] Теги добавлены для больших данных (> 1KB)
- [ ] Теги добавлены для множественных артефактов
- [ ] Имена тегов осмысленные
- [ ] Загрузка из файла используется только когда нужно
- [ ] Нет избыточных загрузок одного и того же файла
- [ ] Комментарии объясняют выбор подхода
