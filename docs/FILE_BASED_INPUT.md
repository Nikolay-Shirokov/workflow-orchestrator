# Файловый ввод пользователя

Файловый ввод позволяет пользователям вводить большие структурированные данные и отвечать на вопросы через текстовые файлы, которые автоматически открываются в редакторе, вместо использования командной строки.

## Обзор

Файловый ввод - это альтернативный способ взаимодействия с workflow orchestrator, который особенно полезен для:

- **Больших промптов**: Удобное редактирование многострочных текстов
- **Структурированных данных**: Работа с YAML, JSON или Markdown
- **Множественных вопросов**: Ответы на серию вопросов в одном файле
- **Сохранение прогресса**: Возможность вернуться к редактированию позже
- **Использование привычных инструментов**: Работа в любимом редакторе

## Преимущества

✅ **Удобство**: Редактирование в полноценном текстовом редакторе  
✅ **Гибкость**: Поддержка различных форматов (Markdown, YAML, JSON, Text)  
✅ **Валидация**: Автоматическая проверка данных перед продолжением  
✅ **Возобновление**: Сохранение прогресса и возможность вернуться позже  
✅ **Оптимизация**: Минимизация размера контекста для снижения затрат на API  

## Быстрый старт

### Шаг 1: Создайте workflow с файловым вводом

```yaml
workflow:
  name: "file-input-example"
  version: "1.0"
  
  settings:
    artifacts_dir: "artifacts/file-input"
    default_input_mode: "file"  # Использовать файловый ввод по умолчанию
  
  roles:
    assistant:
      adapter: "claude-cli"
      model: "claude-sonnet-3.5"
  
  steps:
    - id: "user_input"
      name: "Сбор информации"
      type: "user_input"
      input_mode: "file"  # Использовать файловый ввод для этого шага
      file_format: "markdown"  # Формат файла
      prompt_message: |
        Пожалуйста, ответьте на следующие вопросы:
        
        1. Какую задачу вы хотите автоматизировать?
        2. Какие данные нужны для выполнения?
        3. Какой результат вы ожидаете?
      outputs:
        user_answers: "${artifacts_dir}/user_answers.md"
    
    - id: "process"
      name: "Обработка ответов"
      type: "model"
      role: "assistant"
      depends_on: ["user_input"]
      prompt_template: |
        На основе ответов пользователя создайте план:
        
        ${user_answers}
      inputs:
        user_answers: "${user_answers}"
      outputs:
        plan: "${artifacts_dir}/plan.md"
```

### Шаг 2: Запустите workflow

```bash
workflow-orchestrator run file-input-example.yaml
```

### Шаг 3: Заполните файл

Система автоматически:
1. Создаст файл-шаблон с вопросами
2. Откроет его в вашем редакторе
3. Приостановит выполнение и покажет интерактивное меню

### Шаг 4: Выберите действие

Используйте стрелочки для выбора:
- **Продолжить** (по умолчанию) - прочитать файл и продолжить
- **Отложить** - сохранить состояние и выйти

Нажмите Enter для подтверждения.

## Конфигурация

### Глобальные настройки

Настройте режим ввода по умолчанию для всего workflow:

```yaml
settings:
  default_input_mode: "file"  # "file" или "console"
  default_file_format: "markdown"  # "markdown", "yaml", "json", "text"
  default_editor:
    command: "code"  # VS Code
    args: ["--wait"]  # Ждать закрытия файла
    wait: true
```

### Настройки шага

Переопределите настройки для конкретного шага:

```yaml
steps:
  - id: "user_input"
    type: "user_input"
    input_mode: "file"  # Режим ввода для этого шага
    file_format: "yaml"  # Формат файла
    include_questions: false  # Не включать вопросы в контекст
    editor:
      command: "vim"  # Использовать vim
      wait: true
    prompt_message: "Введите данные..."
```

### Параметры конфигурации

| Параметр | Тип | Значение по умолчанию | Описание |
|----------|-----|----------------------|----------|
| `input_mode` | string | "console" | Режим ввода: "file" или "console" |
| `file_format` | string | "markdown" | Формат файла: "markdown", "yaml", "json", "text" |
| `include_questions` | boolean | false | Включать ли вопросы в контекст |
| `editor.command` | string | auto | Команда для запуска редактора |
| `editor.args` | string[] | [] | Аргументы командной строки |
| `editor.wait` | boolean | true | Ждать закрытия редактора |

## Форматы файлов

### Markdown (рекомендуется)

Удобный для чтения формат с заголовками и форматированием:

```markdown
# Ответы на вопросы

## 1. Какую задачу вы хотите автоматизировать?

Я хочу автоматизировать процесс код-ревью...

## 2. Какие данные нужны для выполнения?

- Исходный код
- Правила проверки
- История изменений
```

### YAML

Структурированный формат для сложных данных:

```yaml
# Ответы на вопросы

question_1:
  text: "Какую задачу вы хотите автоматизировать?"
  answer: "Процесс код-ревью"

question_2:
  text: "Какие данные нужны?"
  answer:
    - "Исходный код"
    - "Правила проверки"
```

### JSON

Формат для программной обработки:

```json
{
  "question_1": {
    "text": "Какую задачу вы хотите автоматизировать?",
    "answer": "Процесс код-ревью"
  },
  "question_2": {
    "text": "Какие данные нужны?",
    "answer": ["Исходный код", "Правила проверки"]
  }
}
```

### Plain Text

Простой текстовый формат:

```
Вопрос 1: Какую задачу вы хотите автоматизировать?
Ответ: Процесс код-ревью

Вопрос 2: Какие данные нужны?
Ответ: Исходный код, правила проверки
```

## Интерактивный режим

После создания файла-шаблона система переходит в интерактивный режим:

```
[INFO] Файл создан: artifacts/session_xxx/user_input.md
[INFO] Файл открыт в редакторе: code
[INFO] Процесс приостановлен

Выберите действие:
> Продолжить
  Отложить

Используйте стрелочки для выбора, Enter для подтверждения
```

### Команды

- **Продолжить** (по умолчанию): Прочитать заполненный файл и продолжить выполнение
- **Отложить**: Сохранить состояние и завершить для последующего возобновления

### Поведение по умолчанию

Если вы просто нажмете Enter без изменения выбора, будет выполнено действие по умолчанию (Продолжить).

## Возобновление процесса

### Сохранение состояния

Когда вы выбираете "Отложить", система:
1. Сохраняет текущее состояние процесса
2. Сохраняет путь к файлу-шаблону
3. Создает резервную копию частично заполненного файла

### Возобновление

Возобновите процесс позже:

```bash
workflow-orchestrator resume session_20260113_120000 workflow.yaml
```

Система автоматически:
1. Проверит наличие заполненного файла
2. Предложит использовать его или создать новый
3. Продолжит выполнение со следующего шага

### Проверка статуса

Проверьте статус приостановленного процесса:

```bash
workflow-orchestrator status session_20260113_120000
```

Вывод:
```
Сессия: session_20260113_120000
Статус: paused
Текущий шаг: user_input (1/3)
Файл ввода: artifacts/session_xxx/user_input.md
Время приостановки: 2026-01-13 12:00:00
```

## Обработка ошибок

### Ошибка создания файла

Если файл не может быть создан:

```
[ERROR] Не удалось создать файл: Permission denied
[INFO] Попытка создания в альтернативной директории...
[INFO] Файл создан: /tmp/workflow_input_xxx.md
```

Альтернативные стратегии:
1. Создание в временной директории
2. Предложение указать путь вручную
3. Переключение на консольный ввод

### Недоступный редактор

Если редактор не может быть запущен:

```
[WARN] Редактор 'code' не найден
[INFO] Попытка использовать системный редактор...
[INFO] Файл для редактирования: artifacts/session_xxx/user_input.md
[INFO] Откройте файл вручную и выберите "Продолжить" когда закончите
```

### Удаленный файл

Если файл был удален пользователем:

```
[ERROR] Файл не найден: artifacts/session_xxx/user_input.md
[INFO] Файл был удален. Создать новый? (y/n)
```

### Некорректные данные

Если данные не проходят валидацию:

```
[ERROR] Ошибки валидации:
  - Вопрос 1: Ответ не может быть пустым
  - Вопрос 3: Ожидается число, получено: "abc"

[INFO] Исправьте ошибки и выберите "Продолжить"
[INFO] Файл: artifacts/session_xxx/user_input.md
```

```yaml

  - id: "survey"
    type: "user_input"
    input_mode: "file"
    file_format: "markdown"
    prompt_message: |
      ## Опрос разработчика
      
      1. Какой язык программирования вы используете?
      2. Сколько лет опыта?
      3. Какие инструменты предпочитаете?
```

### Пример 2: Структурированные данные

```yaml

  - id: "config"
    type: "user_input"
    input_mode: "file"
    file_format: "yaml"
    prompt_message: |
      Заполните конфигурацию проекта:
      
      project_name: ""
      version: "1.0.0"
      dependencies:
        - name: ""
          version: ""
      settings:
        debug: false
        port: 3000
```

```yaml
steps:
  - id: "requirements"
    type: "user_input"

    file_format: "markdown"
    editor:
      command: "code"
      args: ["--wait"]

      ## Нефункциональные требования
```

## Troubleshooting

### Редактор не открывается

**Проблема**: Файл создан, но редактор не запускается

**Решение**:
1. Проверьте, установлен ли редактор:
   ```bash
   which code  # для VS Code
   which vim   # для Vim
   ```

2. Укажите полный путь к редактору:
   ```yaml
   editor:
     command: "/usr/local/bin/code"
   ```

3. Используйте системный редактор:
   ```yaml
   editor:
     command: "$EDITOR"  # Unix/Linux
     command: "notepad"  # Windows
   ```

### Файл не сохраняется

**Проблема**: Изменения в файле не применяются

**Решение**:
1. Убедитесь, что файл сохранен (Ctrl+S / Cmd+S)
2. Закройте редактор перед выбором "Продолжить"
3. Проверьте права доступа к файлу:
   ```bash
   ls -la artifacts/session_xxx/user_input.md
   ```

### Ошибки валидации

**Проблема**: Данные не проходят валидацию

**Решение**:
1. Внимательно прочитайте сообщения об ошибках
2. Проверьте формат данных (YAML, JSON должны быть валидными)
3. Убедитесь, что все обязательные поля заполнены
4. Используйте валидатор формата:
   ```bash
   yamllint user_input.yaml
   jq . user_input.json
   ```

### Процесс не возобновляется

**Проблема**: Не удается возобновить приостановленный процесс

**Решение**:
1. Проверьте ID сессии:
   ```bash
   ls state/
   ```

2. Проверьте статус:
   ```bash
   workflow-orchestrator status <session-id>
   ```

3. Проверьте наличие файла состояния:
   ```bash
   cat state/session_<id>.json
   ```

### Кодировка символов

**Проблема**: Неправильное отображение кириллицы или специальных символов

**Решение**:
1. Убедитесь, что файл сохранен в UTF-8
2. Настройте редактор на UTF-8:
   - VS Code: `"files.encoding": "utf8"`
   - Vim: `set encoding=utf-8`

3. Проверьте кодировку файла:
   ```bash
   file -i user_input.md
   ```
