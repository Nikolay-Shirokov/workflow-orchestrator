# Задача 9: Исправление парсинга markdown для свободного текста

## Проблема

При выполнении workflow пользовательский ввод сохранялся в JSON формате вместо обычного текста, и модель Gemini не получала корректный промпт, отвечая "I'm ready for your first command".

## Анализ

1. **Корневая причина**: Метод `parseMarkdown()` в `user-input-handler.ts` парсил файл как структурированный документ из-за наличия заголовков `##` в шаблоне
2. **Источники проблемы**:
   - Инструкции в шаблоне использовали `## 📝 Инструкции`
   - `prompt_message` в конфигурации содержал `## Что вы хотите создать?`
   - Разделитель `---` добавлял лишний шум

## Решение

### 1. Изменен формат инструкций (src/core/template-generator.ts)
```typescript
// Было:
lines.push('## 📝 Инструкции');

// Стало:
lines.push('<!--');
lines.push('📝 Инструкции:');
lines.push('-->');
```

**Преимущества**:
- HTML комментарии не видны при рендеринге markdown
- Не мешают парсингу структурированного текста
- Инструкции остаются читаемыми в исходном файле

### 2. Убран разделитель из шаблона
```typescript
// Было:
if (step.prompt_message) {
  lines.push('---');
  lines.push('');
  lines.push(step.prompt_message);
}

// Стало:
if (step.prompt_message) {
  lines.push(step.prompt_message);
  lines.push('');
}
```

### 3. Исправлен prompt_message в конфигурации (examples/business-requirements-simple.yaml)
```yaml
# Было:
prompt_message: |
  # Опишите вашу потребность
  
  ## Что вы хотите создать?
  
  [Ваше описание]

# Стало:
prompt_message: |
  # Опишите вашу потребность
  
  **Что вы хотите создать?**
  
  [Ваше описание]
```

### 4. Улучшен промпт для модели
```yaml
prompt_template: |
  Ты - бизнес-аналитик. Пользователь описал свою потребность:
  
  ---
  ${user_need}
  ---
  
  Твоя задача: задать 3-5 ключевых вопросов для уточнения деталей...
```

## Результаты

✅ Данные сохраняются как обычный текст, а не JSON
✅ HTML комментарии не передаются в контекст модели
✅ Шаблон остается читаемым для пользователя
✅ `parseMarkdown()` корректно определяет свободный текст

## Оставшаяся проблема

Модель все еще отвечает некорректно, возможно из-за:
- HTML комментарии все еще присутствуют в контексте
- Нужно дополнительно очищать текст перед передачей модели
- Или использовать другой подход к фильтрации служебной информации
